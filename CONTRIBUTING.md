# Contributing to SheMesh Tribe LLC — Public Ecosystem

Thank you for helping improve the public-facing tools.

## What we accept

- Accessibility improvements  
- Mobile usability improvements  
- Documentation clarity  
- Generic educational content (public-safe)  
- Public-safe examples  
- Bug fixes  
- Performance improvements  
- UI improvements  
- Tests  
- Translations  
- Clarity improvements  

## What we reject

- Secrets of any kind  
- Personal records  
- Customer data  
- Confidential information  
- Trade secrets  
- Proprietary algorithms  
- Protected implementation details  
- Confidential partner information  
- Anything that reconstructs or exposes internal SheMesh systems (e.g. protected engines or protocols)  

**If uncertain whether something is public-safe, leave it out.**

## Public-safe pull-request checklist

Before opening a PR, confirm:

- [ ] No passwords, API keys, tokens, recovery codes or private keys  
- [ ] No private customer or personal data  
- [ ] No proprietary algorithms or trade secrets  
- [ ] No confidential infrastructure or partner details  
- [ ] Changes remain offline-first / local-first where applicable  
- [ ] No new third-party tracking or analytics scripts  
- [ ] UI remains accessible (labels, focus, contrast, keyboard)  
- [ ] Mobile layout still works on small screens  
- [ ] Documentation updated if behaviour changes  

## How to contribute

1. Fork or branch from `main`.  
2. Make focused, public-safe changes.  
3. Test in a browser (especially mobile width).  
4. Open a pull request with a clear description.  
5. Reference any related issue if one exists.  

## Code style

- Vanilla HTML, CSS and JavaScript preferred.  
- Keep dependencies minimal or zero for core public tools.  
- Prefer semantic HTML and clear, readable code.  

## Licence note

Contributions are accepted under the understanding that this is the public interface of SheMesh Tribe LLC. Internal proprietary systems remain outside the scope of this repository.
